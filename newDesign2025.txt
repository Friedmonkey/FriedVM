language design 2025

type byte:
- a full byte for all sorts of types

raw =        0x00,
string =     0x01,   //not that complex but it does store its length

uint8_t =    0x10,   // none - char, byte, uint8, u8
uint16_t =   0x12,   // none - ushort, uint16, u16
uint32_t =   0x13,   // 50u  - uint, uint32, u32
uint64_t =   0x14,   // 50ul - ulong, uint64, u64
int8_t =     0x15,   // none - sbyte, int8, i8
int16_t =    0x16,   // none - short, int16, i16
int32_t =    0x17,   // 50   - the default - int, int32, i32
int64_t =    0x18,   // 50l  - long, int64, i64
float_t =    0x19,   // 50f  - float, float32, f32
double_t =   0x1A,   // 50d  - double, float64, f64

complex types
complex_type=0xFC,   // only used in header, basicly means Read TypedByte system() usefull if u reuse a certain type
struct =     0xFD,   // struct { field int age; }
array =      0xFE,   // array[5]<int>, arr[5]<char> 
pointer =    0xFF,   // ptr<int>, pointer<int>


vt_complex_type:
only used in header, it means read another byte (TypedByte)
basicly it means it stores extra info
so since complex types are stored at the start of .data
vt_complex_type basicly preappends a type, so u only have to define a type once and reuse it

normall in header u would have
array[10]<array[1]<int>>, in the header it would simply be "vt_array" 
and the "[10]<array[1]<int>>" is stored in the data

if we instead use complex type it would be stored in the header
complex_type<array[10]<array[1]<int>>> 
then when its created it gets type "array" and data starts with "[10]<array[1]<int>>" (AT RUNTIME)
so we store its type in the header and then the amount of times used etc only needs the type once
and every derivitive
this is cool but it basicly means we can reuse the same data alot

we wont automate this i think
instead typedef will do it
